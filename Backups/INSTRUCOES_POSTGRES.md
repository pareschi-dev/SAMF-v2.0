# PostgreSQL local do SAMF

## 1. Preparar ambiente

Na raiz do projeto:

```powershell
Copy-Item .env.example .env
notepad .env
```

Preencha `SUA_SENHA` sem colocar a senha no código:

```env
DB_PROVIDER=postgres
DATABASE_URL=postgresql://postgres:SUA_SENHA@localhost:5432/samf
POSTGRES_ADMIN_URL=postgresql://postgres:SUA_SENHA@localhost:5432/postgres
```

Se a senha tiver caracteres reservados em URL, use percent-encoding. Exemplos: `@` vira `%40`, `#` vira `%23` e `%` vira `%25`.

## 2. Instalar dependências

```powershell
& .\.venv\Scripts\python.exe -m pip install -r Scripts\requirements.txt -r Interface_Web\backend\requirements.txt
```

## 3. Criar o banco

O serviço PostgreSQL precisa estar em execução. O script somente cria o banco se ele não existir; não executa `DROP DATABASE`.

```powershell
$env:PYTHONPATH = (Join-Path $PWD 'Scripts')
& .\.venv\Scripts\python.exe Scripts\criar_banco_postgres.py
```

## 4. Migrar integralmente o SQLite

A origem é `samf.db` e nunca é apagada ou alterada. O destino precisa estar vazio. A migração cria as tabelas, converte tipos, preserva IDs, índices, unicidades, chaves estrangeiras, trigger de auditoria e compara as contagens impressas ao final.

```powershell
$env:PYTHONPATH = (Join-Path $PWD 'Scripts')
& .\.venv\Scripts\python.exe Scripts\migrar_sqlite_postgres.py
```

Se o destino já tiver registros, o script aborta para evitar duplicidade. Nenhuma limpeza automática é feita.

## 5. Executar a aplicação usando PostgreSQL

```powershell
$env:PYTHONPATH = (Join-Path $PWD 'Scripts')
& .\.venv\Scripts\python.exe Interface_Web\backend\app.py
```

Acesse `http://127.0.0.1:5000/` e verifique `http://127.0.0.1:5000/api/auth/status`.

## 6. Voltar ao SQLite

No `.env`, altere apenas:

```env
DB_PROVIDER=sqlite
```

O arquivo `samf.db` continua preservado como fonte e fallback.

## Conversões

- `INTEGER PRIMARY KEY AUTOINCREMENT` vira `BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`.
- `INTEGER` vira `BIGINT`.
- `REAL` vira `DOUBLE PRECISION`.
- `DATETIME` vira `TIMESTAMP`.
- Colunas declaradas como `TEXT` permanecem `TEXT` para não corromper valores legados; o SQLite real não declara colunas JSON.
- Os dados são enviados por parâmetros do driver, nunca por concatenação de valores.
- Índices únicos, índices normais, chaves estrangeiras e o bloqueio de exclusão de `auditoria_eventos` são recriados.
- Os testes unitários continuam podendo usar SQLite em memória; PostgreSQL é ativado somente com `DB_PROVIDER=postgres`.
